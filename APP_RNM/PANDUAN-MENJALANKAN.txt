1. SEKALI PER JENDELA POWERSHELL: KENALKAN go DAN node
================================================================================

Go 1.26.8 dan Node 24.21.0 sudah terpasang di mesin ini, tetapi TIDAK ada di
PATH shell. Tanpa langkah ini semua perintah di bawah gagal dengan pesan
"tidak dikenal sebagai nama cmdlet".

  $env:Path = 'C:\Program Files\Go\bin;C:\Program Files\nodejs;' + $env:Path
  Set-Location 'D:\XML\RNM_BRD\OUTPUT_HASIL_RNM\APP_RNM'
  go version        # harus: go version go1.26.8 windows/amd64
  node --version    # harus: v24.21.0

Catatan:
  - Baris pertama hanya berlaku di jendela PowerShell itu. Buka jendela baru,
    ulangi baris itu.
  - Bila ingin permanen, tambahkan kedua folder itu ke Path pengguna lewat
    Windows Settings > System > About > Advanced system settings >
    Environment Variables. Itu perubahan mesin, bukan bagian dari repositori.
  - "make" TIDAK terpasang. Setiap target di Makefile adalah satu-dua perintah
    biasa; panduan ini menulis perintahnya langsung.

2. BACKEND TANPA ORACLE (BISA DIJALANKAN HARI INI)
================================================================================

Jalankan:

  go run ./cmd/api

Log yang benar:

  oracle: ORACLE_DSN kosong - berjalan tanpa database
  http: mendengarkan di :8080

Cek dari jendela PowerShell LAIN, atau dari browser:

  Invoke-WebRequest -UseBasicParsing http://localhost:8080/healthz |
    Select-Object -Expand Content

  Jawaban:  {"status":"sehat","database":"tidak dikonfigurasi"}

  Invoke-WebRequest -UseBasicParsing http://localhost:8080/api/klaim-life/UJI-1

  Jawaban:  kode 503, badan {"galat":"database belum dikonfigurasi"}
            (PowerShell menampilkannya sebagai galat merah; itu memang
            jawaban yang diharapkan tanpa Oracle.)

Berhenti: tekan Ctrl+C di jendela backend. Server menutup rapi, paling lama
10 detik.

Bila ingin berkas exe alih-alih "go run":

  go build -o bin\api.exe .\cmd\api
  .\bin\api.exe

Folder bin\ tidak masuk git.

Mengubah port (bila 8080 sudah dipakai proses lain):

  $env:HTTP_ADDR = ':8081'
  go run ./cmd/api

================================================================================
3. BACKEND DENGAN ORACLE (SETELAH DBA MEMBERI SKEMA UJI)
================================================================================

PENTING: backend TIDAK membaca berkas .env. Berkas .env.example hanya daftar
nama variabel. Nilainya disetel di terminal, dan TIDAK PERNAH ditulis ke
berkas, chat, tiket, atau prompt.

Setel di jendela backend:

  $env:ORACLE_DSN    = 'oracle://<pengguna>:<sandi>@<host>:<port>/<service>'
  $env:ORACLE_SCHEMA = '<nama skema uji dari DBA>'
  $env:IS_PEGA_PROD  = 'false'

Ganti bagian di dalam <...> dengan nilai dari DBA. Skema uji adalah skema yang
DBA sediakan khusus untuk pengembangan, bukan produksi.

Aturan yang ditegakkan kode:
  - ORACLE_DSN terisi tetapi ORACLE_SCHEMA kosong: backend menolak start,
    pesan "konfigurasi: ORACLE_SCHEMA wajib terisi bila ORACLE_DSN terisi".
  - IS_PEGA_PROD=true: migrasi menolak berjalan. Jangan pernah menunjuk alias
    atau instance produksi.

Urutan pertama kali:

  go run ./cmd/api -migrate
    membentuk 7 tabel, 5 sequence, 7 index di skema uji, lalu keluar.
    Log: "migrasi skema <skema>: 8 langkah dijalankan, 0 dilewati, N pernyataan"

  go run ./cmd/api -migrate
    dijalankan ULANG sebagai bukti aman diulang.
    Log yang benar: "0 langkah dijalankan, 8 dilewati"

  go run ./cmd/api
    jalankan server seperti bab 2.

Setelah itu:
  - /healthz menjawab {"status":"sehat","database":"terjangkau"}
  - /api/klaim-life/<id> menjawab 404 {"galat":"klaim tidak ada"} untuk id
    yang belum ada. Data klaim belum ada sampai tiket 02 (register klaim)
    dikerjakan.

Bila sesi berikutnya butuh Oracle lagi, setel ulang ketiga variabel itu.
Env var hilang saat jendela ditutup.

Perintah lain, semua dari folder frontend:

  Kosong berarti "alamat yang sama dengan halaman". Berkas .env tidak masuk

================================================================================
5. CELAH YANG HARUS DIKETAHUI: FRONTEND DEV BELUM BISA BICARA KE BACKEND
================================================================================

Ini ditemukan saat mencoba, bukan dugaan:

  a. vite.config.ts TIDAK punya pengaturan proxy. Permintaan /api/... dari
     halaman jatuh ke server Vite sendiri, dan Vite menjawabnya dengan
     index.html. Halaman tidak pernah menerima JSON dari Go.

  b. Mengisi frontend\.env dengan VITE_API_BASE_URL=http://localhost:8080
     membuat browser memanggil backend langsung, tetapi backend TIDAK mengirim
     header CORS (Access-Control-Allow-Origin). Browser memblokir jawabannya.

  c. Backend tidak menyajikan folder dist/. Jadi jalur "satu asal" (frontend
     dan API dari alamat yang sama) juga belum ada.

Akibatnya hari ini:
  - Backend dan frontend bisa dijalankan dan dicek SENDIRI-SENDIRI (bab 2, 4).
  - Tombol "Buka" di halaman belum sampai ke Go. Ia menampilkan "Gagal membaca
    klaim." atau halaman kosong, apa pun id yang diketik.

Ini bukan cacat tiket 01: AC-nya diuji lewat seam HTTP dan repository, bukan
lewat browser. Tetapi celah ini harus ditutup sebelum ada yang mencoba lewat
browser.

[USULAN] penutup paling kecil, dikerjakan di sesi implementasi berikutnya,
bukan diubah sendiri di sini: proxy di vite.config.ts yang alamat tujuannya
dibaca dari env var, bukan ditulis sebagai literal:

  server: {
    port: 5173,
    proxy: process.env.VITE_PROXY_TARGET
      ? {
          '/api':     process.env.VITE_PROXY_TARGET,
          '/healthz': process.env.VITE_PROXY_TARGET,
        }
      : undefined,
  },

Cara memakainya setelah ada:

  $env:VITE_PROXY_TARGET = 'http://localhost:8080'
  npm run dev

Tanpa CORS, tanpa alamat host di berkas mana pun (ADR-U-0004).

================================================================================
10. ATURAN YANG TIDAK BOLEH DILANGGAR
================================================================================

  1. Nol alamat host, kata sandi, DSN, atau nomor polis sungguhan di berkas
     mana pun: kode, test, .env.example, tiket, prompt, chat. Nilai hanya di
     env var terminal. (ADR-U-0004)
  2. Jangan pernah menunjuk instance atau alias produksi. IS_PEGA_PROD=true
     memang dibuat untuk menolak migrasi.
  3. Uang tidak pernah float. Dari Oracle sebagai teks (TO_CHAR), di Go
     apd.Decimal, di JSON teks, di React string. (ADR-U-0003, ADR-U-0016)
  4. Kode dan nomor tetap teks: "006" bukan 6. (ADR-U-0022)
  5. Data uji selalu berawalan UJI-, tidak pernah data sungguhan.
  6. Berkas .sql dan .go berakhiran baris LF, tanpa BOM. Dijaga .gitattributes
     dan test.
  7. Migrasi hanya terhadap skema uji dari DBA. Instance lain butuh persetujuan
     manusia lebih dulu.
