Go 1.26.8 dan Node 24.21.0 sudah terpasang di mesin ini, tetapi TIDAK ada di

  Set-Location 'D:\XML\RNM_BRD\OUTPUT_HASIL_RNM\APP_RNM'
  go version        # harus: go version go1.26.8 windows/amd64
  node --version    # harus: v24.21.0

Catatan:

    ulangi baris itu.
  - Sudah dibuat PERMANEN untuk akun pengguna mesin ini pada 26 September 2026

    disabled on this system". Pemuat versi cmd (muat-env.cmd) tidak

3. BACKEND DENGAN ORACLE (SETELAH DBA MEMBERI SKEMA UJI)
================================================================================

PENTING: backend Go TIDAK membaca berkas .env sendiri; ia hanya membaca env
var proses. Karena itu ada dua skrip pemuat di folder APP_RNM yang membaca
APP_RNM\.env lalu menyetel env var untuk jendela yang sedang terbuka:

  PowerShell:   . .\muat-env.ps1        (titik, spasi, nama skrip: dot-source)
  cmd.exe:      call muat-env.cmd

Isi APP_RNM\.env (salin dari .env.example; berkas .env tidak masuk git):

  HTTP_ADDR=:8080
  ORACLE_DSN=oracle://<pengguna>:<sandi>@<host>:<port>/<service>
  ORACLE_SCHEMA=<nama skema uji dari DBA>
  IS_PEGA_PROD=false

  - <sandi> boleh dibiarkan apa adanya: muat-env.ps1 menanyakannya saat dimuat,
    tanpa menampilkan dan tanpa menulisnya ke mana pun. muat-env.cmd tidak
    punya prompt tersembunyi, jadi untuk cmd isi sandinya di .env.
  - Bagian <...> lainnya diisi dari nilai yang diberikan DBA.
  - ORACLE_DSN tidak pernah dicetak kedua skrip ke layar.

Tanpa skrip, ketiga nilai itu bisa disetel langsung di jendela backend:

  $env:ORACLE_DSN    = 'oracle://<pengguna>:<sandi>@<host>:<port>/<service>'
  $env:ORACLE_SCHEMA = '<nama skema uji dari DBA>'
  $env:IS_PEGA_PROD  = 'false'

Skema uji adalah skema KOSONG yang DBA sediakan khusus untuk pengembangan,
bukan produksi, dan bukan POOLDATA (lihat peringatan di bawah).

PERINGATAN SEBELUM MENJALANKAN TEST BERTAG db (bab 7):

  `go test -tags=db` MENGHAPUS tabel di skema yang ditunjuk ORACLE_SCHEMA.
  Yang dihapusnya termasuk OS_AKSEPTASI_KLAIM_LIFE, tabel datar warisan.
  Skema uji harus skema KOSONG yang dibuat DBA khusus untuk itu - bukan
  POOLDATA, dan bukan skema apa pun yang memuat tabel warisan sungguhan,
  sekalipun di instance pengembangan.

  Karena itu test bertag db menuntut satu env var lagi, sebagai pengakuan
  sadar bahwa skema itu memang boleh dihapus isinya:

    $env:ORACLE_SKEMA_UJI = 'true'

  Tanpa itu test BERHENTI dengan galat, bukan lewat. Menunjuk POOLDATA juga
  ditolak, dan ORACLE_SKEMA_UJI=true tidak mengubahnya.

  Yang TIDAK dipagari: `go run ./cmd/api -migrate`. Ia hanya membuat objek,
  tidak pernah menghapusnya.

MEMBONGKAR SKEMA UJI

  go run ./cmd/api -migrate-down

  Menjalankan jalur mundur setiap langkah yang TERCATAT selesai di T_MIGRASI,
  dari yang terakhir ke yang pertama, lalu keluar. Log menyebut tiap langkah
  yang dibongkar.

  Dipagari sama persis dengan test bertag db, dan menolak dengan galat bila:
    - IS_PEGA_PROD=true
    - ORACLE_SKEMA_UJI belum 'true'
    - ORACLE_SCHEMA memuat POOLDATA

  Kenapa lewat flag ini dan bukan sqlplus: membongkar dengan menyalin isi
  berkas *_down.sql ke sqlplus MELEWATI T_MIGRASI, sehingga langkah yang tidak
  pernah tercatat ikut dibongkar dan catatannya jadi berbohong. Flag ini
  membongkar HANYA yang tercatat.

  -migrate dan -migrate-down tidak boleh diberikan bersamaan.

Aturan yang ditegakkan kode:
  - ORACLE_DSN terisi tetapi ORACLE_SCHEMA kosong: backend menolak start,
    pesan "konfigurasi: ORACLE_SCHEMA wajib terisi bila ORACLE_DSN terisi".
  - IS_PEGA_PROD=true: migrasi menolak berjalan. Jangan pernah menunjuk alias
    atau instance produksi.

Urutan pertama kali:

5. BAGAIMANA FRONTEND DEV BICARA KE BACKEND: PROXY VITE
================================================================================

Saat dev, halaman dilayani Vite di port 5173 dan backend Go di port 8080.
Browser tidak boleh memanggil 8080 langsung (backend tidak mengirim header
CORS, jadi browser memblokirnya). Jalan keluarnya: Vite MENERUSKAN permintaan
/api/* dan /healthz ke backend, sehingga bagi browser semuanya satu alamat.

Pengaturannya ada di vite.config.ts dan dibaca dari frontend\.env:

  DEV_PROXY_TARGET=http://localhost:8080

  - Terisi  : /api dan /healthz diteruskan ke alamat itu (keadaan normal).
  - Kosong  : tanpa proxy. Permintaan /api jatuh ke Vite sendiri dan dijawab
              index.html, jadi tombol "Buka" tidak pernah sampai ke Go.
  - Nilainya tidak ikut ke bundel browser, dan nol alamat host tertulis di
    kode (ADR-U-0004). Samakan port-nya dengan HTTP_ADDR di APP_RNM\.env.

7. UJI SEBELUM DAN SESUDAH MENGUBAH APA PUN
================================================================================

Dari folder APP_RNM:

  go vet ./...
  go test ./...
    harus: ok untuk setiap paket inti/..., modul/..., uji/..., dan cmd/api;
    paket lain "[no test files]".

  go test -tags=db ./...
    tanpa ORACLE_DSN: test bertag db SKIP dengan pesan
    "lewati: skemauji: ORACLE_DSN belum dikonfigurasi". Itu perilaku yang
    benar, bukan lulus diam-diam.
    dengan ORACLE_DSN + ORACLE_SCHEMA + ORACLE_SKEMA_UJI=true: seluruhnya
    harus PASS. Test membuat skema uji dari migrasi yang sama dengan aplikasi,
    mengisi data buatan berawalan UJI-, lalu membongkarnya.
    Baca peringatan bab 3 lebih dulu: test ini MENGHAPUS tabel, dan hanya
    "ORACLE_DSN kosong" yang dijawab SKIP. Salah konfigurasi, menunjuk
    produksi, atau menunjuk skema yang bukan skema uji MENGGAGALKAN test.

  gofmt -l .
    harus tidak mencetak apa pun.

Dari folder APP_RNM juga (npm tidak lagi dari folder frontend):

  npm run typecheck
  npm test
    harus: seluruh berkas uji passed.
  npm run build
    harus: tsc bersih, lalu "built in ... ms".

Gabungan yang setara "make check" (make tidak terpasang):

  go build ./... ; go vet ./... ; go test ./...
  npm run typecheck ; npm test

10. ATURAN YANG TIDAK BOLEH DILANGGAR
================================================================================

  1. Nol alamat host, kata sandi, DSN, atau nomor polis sungguhan di berkas
     mana pun: kode, test, .env.example, tiket, prompt, chat. Nilai hanya di
     env var terminal. (ADR-U-0004)
  2. Jangan pernah menunjuk instance atau alias produksi. IS_PEGA_PROD=true
     memang dibuat untuk menolak migrasi.
  3. Uang tidak pernah float. Dari Oracle sebagai teks (TO_CHAR), di Go
     apd.Decimal, di JSON teks, di React string. (ADR-U-0003, ADR-U-0016)
  4. Kode dan nomor tetap teks: "006" bukan 6. (ADR-U-0022)
  5. Data uji selalu berawalan UJI-, tidak pernah data sungguhan.
  6. Berkas .sql dan .go berakhiran baris LF, tanpa BOM. Dijaga .gitattributes
     dan test.
  7. Migrasi hanya terhadap skema uji dari DBA. Instance lain butuh persetujuan
     manusia lebih dulu.
  8. Test bertag db MENGHAPUS tabel. Skema uji tidak pernah POOLDATA, dan
     tidak pernah skema yang memuat tabel warisan sungguhan.
